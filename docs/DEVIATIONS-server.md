# Server: known deviations from C XPilot 4.5.5

The simulation runs one tick per C frame at the map's `framesPerSecond` and uses C's float (`DFLOAT`)
arithmetic, so with the same map, options and inputs it matches the C server frame for frame. The golden
traces in `server/src/test/resources/ctrace/` check that bit for bit (`CTraceTest`; `ModeTraceTest` for the ball
connector, race checkpoints and lap times, and asteroid motion). The deviations below
are deliberate.

| Area | C | JXPilot | Why |
|---|---|---|---|
| `in_range_acd` across the seam | four fixed shifts; misses objects on opposite sides of the seam that did not cross it | shifts by the closest world copy | C bug; results differ only for end points exactly half a world apart. |
| Random numbers | Mersenne Twister `rfrac()`, static `keep_rand` in `Thrust()`, extra `rfrac()` draws (cloak visibility) | one seeded xorshift per world; thrust sparks and bursts seeded from (tick, id) so clients can replay them | Different sequences by design; everything random differs in detail, nothing else. |
| Key input | every key event of a client packet | the client sends its key mask; the server handles the edges between consecutive masks once per tick (= C frame) | Our protocol. A press and release inside one tick is lost. |
| Keys after `Go_home` | `last_keyv`/`prev_keyv` cleared; the next keyboard packet (sent on a key change) brings the full state | held keys are ignored until the client's mask changes, then all held keys count as pressed | Same effect (lead decision S9). |
| Default engine settings | `Init_player` 45/30/0.12; the client then sends its own settings | 45/35/0.12 (alternate 35/25/0.12), the C client's defaults, until SETTINGS arrives | Lead decision S2. The C client sends settings as 1/256 fixed point, so a C server holds 30/256 = 0.1171875 for 0.12; our SETTINGS carries floats. |
| Rounds: `gameDuration` | the server log says "Server will stop in N minutes." when the first human enters; each frame sends the seconds left only when they change (else the round time), and `End_game` kicks every player with "shutting down: ..." | the same wall-clock timer, game over and 30 * FPS shutdown (`Rounds`, `SimGameHost`, `Server`); no log line; TIMERS carries the seconds left in every snapshot while the timer runs, and the shutdown ends every connection with DISCONNECT (shutdown) | The native protocol sends HUD timers as state, not as one-off packets. |
| Ball life | `LONG_MAX`, counted down every frame; "loose for N frames" is `LONG_MAX - life` | 2^52 (exact in a double), the same countdown and message | `Objects.life` is a double. |
| Connector reach (`pl->ball`) | a plain pointer: after the ball is deleted the slot may hold another object, and C can then "connect" to it | the handle is checked to still be a live ball | C undefined behaviour. |
| Temporary wormholes | unlimited (`realloc`); `remove_temp_wormhole` leaves the moved wormhole's `itemID` stale | at most 64 at a time; the moved wormhole's object index is updated | Fixed pool; C bug. |
| Warp of a removed temporary wormhole | `break` leaves the whole player loop for this frame | only this ship's warp ends | C bug. |
| Race respawn and asteroid placement | `rfrac()` draws (Mersenne Twister) | the world RNG (xorshift) | As "Random numbers" above. |
| `Give_best_player_bonus` with nobody eligible | reads an unset array entry | announces nothing | C undefined behaviour. |
| Login messages (`Handle_login`) | "Welcome to ...", "X (realname) has entered ..." | the network layer (`SimGameHost`) sets them in C's place (before the round-delay message), without the real name: "X has entered ..." / "X (team N) has entered ..." | Our CONNECT carries no real name. |
| Login name check (`Check_names`) | nick must start with 'A'..'Z' (the C client capitalizes it), else E_INVAL | any non-empty name; duplicates are refused case-insensitively | Clients other than C's do not capitalize. |
| Chat (`Handle_talk`) | "god:" lines go to the server admin log; partial names also match the real name | "god:" lines go to `adminMessageFileName` when it is set (the entry has no real name, host, address or display); names only | No real names on our protocol; C's default log file is LIBDIR/log, ours is none. |
| Team change and ship shape | `/team N` (C has no team-change packet); PKT_SHAPE only at login | CHANGE_TEAM is handled as `/team N`; the shape comes with CONNECT and a later SHAPE message is ignored | Same behaviour on our protocol. |
| Paused ships on the wire | `Send_paused(x, y, count)` | a SHIP record with the PAUSED flag (no count) | Our protocol. |
| Floating point | GCC may fuse multiply-adds (arm64 `fmadd`) | separate float operations | Matters only for products of non-trivial floats added together (coriolis, local gravity tables); the golden traces show no difference. |
| Robot hooks of kills (`Robot_war`, `Robot_reset_war`, crash re-homing) | called inside the movement and collision code, at the moment of the kill or crash | run from the KILL/CRASH events right after the collision phase of the same frame, before the kill loop | The robot manager reacts to sim events instead of hooks in the sim. Only the order of `Robot_war`'s `rfrac()` among other collision-phase draws differs. |
| Defaults file (`parseDefaultsFile`) | `LIBDIR/defaults`; a missing file is skipped silently | XPilot's `lib/defaults`, bundled in the jar; `--defaults FILE` replaces it, `--defaults none` skips it, and a named file that cannot be read stops the server with an error | No install directory. A typo in a file you named should not quietly give you different physics. |
| Map lookup (`openMapFile`, fileparser.c) | the name as given, then `.xp`, then `.map` (and `.gz` variants with `COMPRESSED_MAPS`) in the current directory, then the same in `MAPDIR` for a name without '/'; no `mapFileName` means `MAPDIR/default.xp` | a name without '/', '\\' or a drive letter is first a map bundled in the jar (case-insensitive, with or without `.xp`), then the current directory with C's extension order; a value with a path is only a file, with C's extension order; no compressed maps; an unknown map is an error listing the bundled names; no `mapFileName` means the bundled `default` (C's default map) | No install directory: the bundled maps take `MAPDIR`'s place, ahead of the current directory so that `--map default` always means the real default map (`--map ./default.xp` reaches a local copy). |
| Password file (`passwordFileName`) | `LIBDIR/password` unless the option names another; a missing file is skipped silently | read only when the option is given; a named file that cannot be read stops the server with an error | No install directory (as the defaults file). |
| Wreckage on the wire (frame.c:802-807) | sent only when the client's spark probability is not 0 or wreckage is deadly; the shape's high bit marks deadly wreckage | always sent; shape is `info & 0x7F`, no deadly bit | Our client has no spark-probability setting and does not draw deadly wreckage differently. |
| `denyHosts` | the list is only built when an operator changes the option at run time (`Set_deny_hosts` is its tuner), so a configured list never takes effect (C bug); IPv4 only; splits on `,;: \t\n` | applied from the start, to every packet outside a session before anything else (as `Check_address` would); IPv4 and IPv6, `addr`, `addr/prefix` or `addr/dotted.mask`; splits on commas, semicolons and whitespace; mask 0 / prefix 0 skipped as in C | The option is meant to work. ':' is part of IPv6 addresses. |
| `serverHost` | the contact socket binds to that host; it is also reported to the meta server | used as the bind selector when `--bind` is not given | No meta server. |
| `logRobots` line | `"DD Mon HH:MM:SS NAME (n, realname) starts at startpos B."` on stdout | the same text on the server log (stderr, with every other server message) | Our server writes one log. |
| Random parts of the frame code (`Frame_shots`: random items, confused mines' friendliness) | world `rfrac()` per client per frame | a snapshot-local RNG seeded from the tick and viewer | Kept: C's frame code draws from the world RNG once per viewer, so the game's random sequence would depend on how many clients are connected (and on their views); ours stays the same however many watch. |
| Snapshot culling (`Frame_parameters` view rectangle, `inview`) | objects strictly inside the connection's `view_width x view_height` | inside the DISPLAY view plus 128 px on each side (`SnapshotBuilder.VIEW_MARGIN`; bursts 400 px more) | The client interpolates ships and extrapolates shots between snapshots; without the margin objects would pop in or vanish inside the view. |
| Deflector object lookup | C's cells are kept current by every move | the spatial grid is rebuilt for each deflector (and cannon danger) query | Kept: an internal difference only; the query returns the same objects in the same order. |
| Login queue messages (`ENTER_QUEUE`, `Queue_ack`) | the client asks for a queue place (ENTER_QUEUE) and re-asks every 10 s; the server acks the position every 3*FPS frames and, when admitted, the login port | the client's CONNECT is answered with REJECT QUEUED and its position; the client resends CONNECT (same nonce) every second and the server answers each; an admitted player's next CONNECT is accepted. A player who finds a free base and nobody waiting joins at once (C queues it and admits it on the next queue pass) | Our CONNECT/ACCEPT handshake; the queue rules, positions, limits (20 places, two per address), the 30*FPS timeout, admission pacing and `/queue`/`/advance` are C's. |
| Player names in commands (`Get_player_index_by_name`) | partial names also match the real name; a robot's real name is copied from `robotRealName` when it joins | humans have no real name; robots match the current `robotRealName` | No real names on our protocol. |
| `/kick` of oneself | the connection is destroyed at once | dropped at the start of the next tick | The operator's own message is being delivered. |
| Over-long command replies | `sprintf` into a 256-byte buffer (overflows with long arguments) | replies are cut to 255 characters | C undefined behaviour. |
| Stale alliance invitation (`Cancel_invitation`) | an invitee who left: reads a stale slot | the invitation is dropped without a message (a new player reusing the id is treated as the invitee, as C) | C undefined behaviour. |
| Alliance marks on the wire | the alliance character in PKT_SCORE | its own reliable message PLAYER_ALLIANCE (31), sent when a player's alliance changes | Our protocol. |
| Options changed with `/set` | the server sends no option values after login (clients get the map and the rules at login only) | the same: connected clients keep the configuration they got when they joined; a JXPilot client's own-ship prediction and thrust sparks use those values until the server's snapshots correct them; newcomers get the start-up configuration | C pushes nothing either. |
| `/set robotTeam` outside 0..9 | the dummy tuner stores it; the robot code then indexes `World.teams` out of range | the value becomes 0 (Robot_init's clamp, robot.c:601) | C undefined behaviour (the Java server would crash). |
| Accepting a leftover invitation from an ally (`Accept_alliance`) | an invitation made before both ended up in one alliance merges that alliance into itself (`Merge_alliances` then dissolves it: a crash) | the invitation is dropped and nothing else happens | C crash. |
