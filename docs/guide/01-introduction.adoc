JXPilot is a reimplementation of https://www.xpilot.org/[XPilot] 4.5.5, the classic multiplayer
gravity war game, in Java 25 with LWJGL and OpenGL. You fly a small triangular ship through a map of
walls, gravity wells, cannons and fuel stations, and fight other players and robots. Thrust has
inertia, gravity pulls you into walls, and fuel runs out.

JXPilot's goals:

* *Feel like XPilot.* The physics, rules and look are ported from the XPilot C sources, and checked
  against the original server frame by frame.
* *Use the original maps unchanged.* It reads XPilot's block-based `.xp` map files and server option
  files as they are. The 19 maps from the XPilot 4.5.5 distribution ship with it
  (<<06-config-and-maps.adoc#shipped-maps,Shipped maps>>).
* *Run anywhere Java runs*: Windows, macOS and Linux, on x64 and arm64.
* *Run well on modern networks*: VPNs, multi-homed hosts and IPv6
  (<<04-running-a-server.adoc#binding,Network binding>>).

[[disclaimer]]
== Relationship to XPilot

IMPORTANT: *Independent derivative port.* JXPilot is an independent port of XPilot 4.5.5 to the JVM.
The original XPilot authors (Bjørn Stabell, Ken Ronny Schouten, Bert Gijsbers, Dick Balaska, and the
many XPilot contributors) were *not involved* in this project and do not endorse it. Please don't send
them bug reports about JXPilot; open an issue at https://github.com/awkay/jxpilot/issues instead.

JXPilot is a derivative work of XPilot and, like XPilot, is free software under the GNU General Public
License, version 2 or later (<<09-appendices.adoc#licensing,Licensing and credits>>).

JXPilot uses its own network protocol, so today a JXPilot client cannot join an original XPilot server,
and an original XPilot client cannot join a JXPilot server. Playing on original servers is planned
(<<07-client-reference.adoc#xpilot-protocol,Playing on original XPilot servers>>).

== Status: what works today

JXPilot is a *work in progress*. It is not yet a playable game. This table is the honest state of
things. "Main" means merged and in the release downloads. "Unmerged branch" means the code is written
and tested on a development branch, but not yet merged or in a release.

[cols="3,2,5",options="header"]
|===
|Area |State |Notes

|Map and option file parsing
|Main
|All XPilot map symbols, `\multiline:`, `\override:`, `define:`/`expand:`; all 19 shipped maps load.

|Map viewer
|Main
|`--view-map`: fly a free camera over any map, with the radar, filled or outlined walls, and a
`--demo` mode that animates fake ships, shots, items and the HUD
(<<07-client-reference.adoc#viewer-flags,Viewer flags>>).

|Client drawing (ships, shots, items, radar, HUD)
|Main
|Ported from the C client's painters. Visible in `--demo`; in a real game once networking is merged.

|Server simulation
|Main
|Runs one step per XPilot frame at the map's `framesPerSecond`, and matches the C server bit for bit
on recorded reference traces. Ported: movement, gravity, walls and crashes, ships, shields, fuel,
shots, cannons, collisions, debris, scoring with score popups, rounds and game over, limited lives,
and pausing (<<03-playing.adoc#rounds,Rounds, lives and game over>>,
<<03-playing.adoc#pausing,Pausing>>). Not yet ported: items and the race, treasure and ball rules (M2).
Not yet connected to the network server.

|Network server (`ServerMain`), binding, rate limits
|Unmerged branch (`server-net`)
|Runs end to end with a stand-in game: players can connect and chat, ships float. See
<<04-running-a-server.adoc#running-a-server,Running a server>>.

|Client networking (connect, receive the map, snapshots, HUD models, key bindings)
|Unmerged branch (`client-net`)
|A headless test client exists; the windowed game client is not wired up yet.

|Playing on original XPilot 4.5.5 servers
|Unmerged branch (`xp-compat`), planned
|The XPilot protocol codecs are written; there is no command-line option for it yet.

|Robots
|Planned
|Robot options are parsed; robots are not implemented.

|Items, balls, treasures, targets, race mode, asteroids
|Planned
|Parsed from maps and drawn by the viewer; no game rules yet.

|Configurable keys, sound
|Planned
|Default XPilot keys are built in (<<03-playing.adoc#controls,Controls>>).
|===

The development plan has three milestones:

M1, playable core:: map rendering, ship movement, gravity and walls, shields, fuel, shots, cannons,
wormholes, death and respawn, scores, chat, robots, radar, HUD, basic team play.
M2:: items, balls and treasures, targets, checkpoints and races, asteroids.
M3:: polish: a configurable keys file; sound if it is cheap.

Out of scope: the XPilot map editor, replay recording, the metaserver and server browser, and the
X11-specific parts of the C client.
