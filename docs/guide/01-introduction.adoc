JXPilot is a reimplementation of https://www.xpilot.org/[XPilot] 4.5.5, the classic multiplayer
gravity war game, in Java 25 with LWJGL and OpenGL. You fly a small triangular ship through a map of
walls, gravity wells, cannons and fuel stations, and fight other players and robots. Thrust has
inertia, gravity pulls you into walls, and fuel runs out.

JXPilot's goals:

* *Feel like XPilot.* The physics, rules and look are ported from the XPilot C sources, and checked
  against the original server frame by frame.
* *Use the original maps unchanged.* It reads XPilot's block-based `.xp` map files and server option
  files as they are. The 19 maps from the XPilot 4.5.5 distribution ship with it
  (<<06-config-and-maps.adoc#shipped-maps,Shipped maps>>).
* *Run anywhere Java runs*: Windows, macOS and Linux, on x64 and arm64.
* *Run well on modern networks*: VPNs, multi-homed hosts and IPv6
  (<<04-running-a-server.adoc#binding,Network binding>>).

[[disclaimer]]
== Relationship to XPilot

IMPORTANT: *Independent derivative port.* JXPilot is an independent port of XPilot 4.5.5 to the JVM.
The original XPilot authors (Bjørn Stabell, Ken Ronny Schouten, Bert Gijsbers, Dick Balaska, and the
many XPilot contributors) were *not involved* in this project and do not endorse it. Please don't send
them bug reports about JXPilot; open an issue at https://github.com/awkay/jxpilot/issues instead.

JXPilot is a derivative work of XPilot and, like XPilot, is free software under the GNU General Public
License, version 2 or later (<<09-appendices.adoc#licensing,Licensing and credits>>).

JXPilot servers and clients talk their own network protocol. The JXPilot client also speaks XPilot's
protocol, so it can join an original XPilot 4.5.5 server
(<<07-client-reference.adoc#xpilot-protocol,Playing on original XPilot servers>>). An original XPilot
client cannot join a JXPilot server.

[[status]]
== Status: what works today

JXPilot is a *work in progress*, but it is playable: you can fly, fight and score against robots and
other players on the JXPilot server, or play on an original XPilot server. This table is the honest
state of things.

[cols="3,2,5",options="header"]
|===
|Area |State |Notes

|Game client
|Works
|Joins a JXPilot server (`--connect`), starts its own server for a quick game (`--local`), or joins an
original XPilot server (`xp://`). Draws the game as the XPilot client does, with the HUD, radar, score
list, messages and talk line (<<07-client-reference.adoc#client-reference,Client reference>>).

|Java server: core game
|Works
|Movement, gravity, walls and crashes, shields, fuel, shots, cannons, wormholes, collisions, debris,
wreckage, scoring with score popups, rounds and limited lives, and pausing, with XPilot's
`lib/defaults` settings. It matches the C server frame for frame on recorded reference traces. Each
option's status is in <<05-server-options.adoc#server-options,the option reference>>.

|Java server: items and weapons
|Works
|All 21 items and the weapons and devices they give: missiles, mines, lasers, nuclear and cluster
weapons and the other modifiers, cloak and sensors, ECM, tractor and pressor beams, transporter,
deflector, phasing, hyperjump, emergency thrust and shield, autopilot, tanks; cannon weapons and
defences; player locks and viewing through a lock. Checked against 21 recorded reference games of the
C server (<<03-playing.adoc#items,Items and weapons>>).

|Java server: robots
|Works
|XPilot's default robot, with the 38 robot personalities of XPilot's robots file
(<<04-running-a-server.adoc#robots,Robots>>).

|Java server: network
|Works
|One UDP port, flexible address binding for VPNs and multi-homed hosts, abuse limits
(<<04-running-a-server.adoc#running-a-server,Running a server>>).

|Java server: game modes
|Works
|Ball games and treasures (<<03-playing.adoc#ball-games,Ball games>>), targets, races, asteroids,
temporary wormholes and `gameDuration`. Checked against 15 recorded reference games of the C server,
replayed with the C server's own random numbers.

|Java server: commands and alliances
|Works
|The `/` commands (`/team`, `/ally`, `/get`, ...), operator commands with a password (`/set` and more),
alliances, custom ship shapes, the login queue and the message of the day
(<<03-playing.adoc#commands,Commands>>, <<04-running-a-server.adoc#operators,Operator commands>>).

|Client options and look
|In progress
|XPilot's button bar (QUIT, ABOUT, MENU), the CONFIG panel with "Save Configuration", XPilot's score
list and per-role fonts are done, and every XPilot client resource is accepted in `~/.xpilotrc` or as
`--RESOURCE VALUE` (<<07-client-reference.adoc#client-resources,Client resources>>). Still in progress:
XPilot's look options, such as the packet meters, the clock, textures and colours.

|Map viewer
|Works
|`--view-map`: a free camera over any map, and a `--demo` mode
(<<07-client-reference.adoc#viewer-flags,Viewer flags>>).

|Lag hiding
|In progress
|Your own ship is no longer drawn a frame behind: the client predicts it forward from the newest frame
the server sent and blends corrections in over a few screen frames. Your keys still take a round trip
to the server, plus the wait for its next frame. Predicting your keys, shots and exhaust on the client
(`docs/latency-fixes.md` in the source) is future work.

|Sound
|Works
|XPilot's sound events, played with free (CC0) sound effects (<<03-playing.adoc#sound,Sound>>).

|Key bindings
|Works
|XPilot's default keys, changeable with an XPilot-format `~/.xpilotrc`, and a key help overlay on
kbd:[F1] (<<03-playing.adoc#key-bindings,Changing the keys>>).
|===

The development plan has three milestones:

M1, playable core:: map rendering, ship movement, gravity and walls, shields, fuel, shots, cannons,
wormholes, death and respawn, scores, chat, robots, radar, HUD, basic team play. Done.
M2:: items, balls and treasures, targets, checkpoints and races, asteroids, alliances and the `/`
commands. Done.
M3:: polish: a configurable keys file and sound. Done.

Out of scope: the XPilot map editor, replay recording, the metaserver and server browser, and the
X11-specific parts of the C client.
