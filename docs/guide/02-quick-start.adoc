This chapter gets JXPilot running from a release download, without building anything. To build from
source instead, see <<08-building.adoc#building,Building from source>>.

[[downloads]]
== Downloads

Every release on https://github.com/awkay/jxpilot/releases has these files. `VERSION` stands for the
release number, for example `0.2.0`.

[cols="3,5,2",options="header"]
|===
|File |What it is |Needs Java 25?

|`jxpilot-client-VERSION.jar`
|The client, for Windows, macOS and Linux on x64 and arm64 (one jar for all of them).
|Yes

|`jxpilot-server-VERSION.jar`
|The headless server, for any operating system.
|Yes

|`jxpilot-maps-VERSION.zip`
|The 19 original XPilot maps and the license, for editing or for other XPilot programs. You don't need
it to play: the jars and applications have the maps built in.
|-

|`JXPilot-VERSION-macos-arm64.zip`, `-macos-x64.zip`, `-linux-x64.tar.gz`, `-linux-arm64.tar.gz`,
`-windows-x64.zip`
|The client as an application with its own Java runtime and the maps built in.
|No

|`jxpilot-guide-VERSION.zip`
|This guide as HTML.
|-

|`openal-soft-source-COMMIT.tar.gz`
|The source of OpenAL Soft, the sound library inside the client (its LGPL licence asks us to offer it).
|-

|`SHA256SUMS.txt`
|SHA-256 checksums of all the files above.
|-
|===

To check a download, put it next to `SHA256SUMS.txt` and run
`sha256sum -c SHA256SUMS.txt --ignore-missing` (Linux), `shasum -a 256 -c SHA256SUMS.txt --ignore-missing`
(macOS) or `Get-FileHash FILE` (Windows PowerShell; compare the hash by eye).

[[java]]
== Installing Java 25

The jars need a Java 25 (or newer) runtime. The application downloads (`JXPilot-VERSION-...`) don't.

* Any Java 25 distribution works. Eclipse Temurin is a good free choice: https://adoptium.net/
  (choose version 25). On macOS you can also use `brew install --cask temurin`.
* Check it with `java -version`. The first line must say version 25 or higher. If it shows an older
  version, your `PATH` finds another Java first; run the jar with the full path to the Java 25 `java`
  binary instead.

[[run-client]]
== Playing right away: a game against robots

[source,shell]
----
java -jar jxpilot-client-VERSION.jar --local --map default
----

`--local` starts a JXPilot server inside the client, reachable only from your own computer, and joins
it. Robots join too (four by default), so you have someone to fight. `default` is one of the 19 maps
built into the jar; `--list-maps` lists them all, and any of them works the same way
(`--map tourmination`). To play a map file of your own, give a path: `--map ./mymap.xp`
(<<07-client-reference.adoc#client-map-names,Map names>>).
Your player name is your login name; choose another with `--name`. The keys are XPilot's: kbd:[A] and
kbd:[S] turn, kbd:[Shift] thrusts, kbd:[Enter] fires, kbd:[Space] is the shield, kbd:[M] opens the talk
line and kbd:[Esc] quits (<<03-playing.adoc#controls,Controls>>).

To look at a map without playing, use the map viewer:
`java -jar jxpilot-client-VERSION.jar --view-map default` (add `--demo` to
see ships, shots and the HUD in action; <<07-client-reference.adoc#viewer-flags,Viewer flags>>).

[[platform-notes]]
=== Platform notes

macOS::
GLFW, the windowing library, needs the Java option `-XstartOnFirstThread` on macOS, and a jar cannot
set Java options. The client jar handles this itself: when the option is missing it starts a second
Java process with the same arguments plus `-XstartOnFirstThread` and the recommended options, and
passes its output and exit status through. You don't need to do anything. Set the environment
variable `JXPILOT_NO_RELAUNCH=1` to turn this off, for example when you start Java with
`-XstartOnFirstThread` yourself (<<07-client-reference.adoc#launcher,The launcher>>).

Linux::
The client needs a graphics driver with OpenGL 3.3 and an X11 or Wayland desktop session. Run
`java -jar ...` as on the other systems. For a smoother game, add the recommended options:
`java -XX:+UseZGC --enable-native-access=ALL-UNNAMED -jar jxpilot-client-VERSION.jar ...`.

Windows::
Run the same command in PowerShell or Command Prompt. In a path to a map file of your own, `\` works
as well as `/`: `java -jar jxpilot-client-VERSION.jar --view-map .\mymap.xp`.

NOTE: The client has been tested most on macOS (Apple Silicon). The Windows and Linux files are built
by the same release process, with less testing so far. Please report problems.

[[app-images]]
== Running the application downloads (no Java needed)

The `JXPilot-VERSION-PLATFORM` archives contain the client with a trimmed Java runtime and the maps.
Started without arguments, the application starts a game against robots on the bundled `default` map
(as `--local --map default`); started from a terminal it takes the same flags as the jar.

[cols="1,3,4",options="header"]
|===
|System |Start it |With flags, from a terminal

|macOS
|Unzip, then double-click `JXPilot.app` (first see <<gatekeeper>>).
|`JXPilot.app/Contents/MacOS/JXPilot --view-map planetx --demo`

|Linux
|`tar xzf JXPilot-VERSION-linux-x64.tar.gz`, then run `JXPilot-VERSION-linux-x64/JXPilot/bin/JXPilot`.
|`.../JXPilot/bin/JXPilot --local --map /path/to/my.xp`

|Windows
|Unzip, then double-click `JXPilot\JXPilot.exe`. A console window opens next to the game window and
shows its messages.
|`JXPilot\JXPilot.exe --view-map C:\path\to\my.xp`
|===

The maps are inside the client jar in the application, so they are found by name as with the jar.

[[gatekeeper]]
=== macOS: "JXPilot is damaged and can't be opened"

The macOS applications are not signed or notarized by Apple (that needs a paid Apple developer
account). macOS marks every downloaded file as quarantined, and for an unsigned application it then
says the app "is damaged" or "cannot be verified". The app is fine. Remove the quarantine mark once,
in Terminal, in the directory where you unzipped it:

[source,shell]
----
xattr -dr com.apple.quarantine JXPilot.app
----

Then double-click it as usual. Only do this for files you downloaded from the JXPilot releases page
and checked against `SHA256SUMS.txt`. The jars are not affected: they run in the `java` you installed.

[[run-server]]
== Running a server

[source,shell]
----
java -jar jxpilot-server-VERSION.jar --map default -noQuit
----

The server prints the addresses it listens on and runs until you press kbd:[Ctrl+C]. Without `-noQuit` it
stops by itself when the last human player leaves (or when nobody joins within 5 minutes), as the original
XPilot server does. For example, with
`--bind loopback --port 15999`:

----
listening on 127.0.0.1:15999 (lo0)
listening on [::1]:15999 (lo0)
serving map 'The Newbie Globe' (170x170 blocks) at 12 frames/s
----

Players connect to one of the listed addresses on UDP port 15345 (the default). Robots fill the game
while humans play (four by default). To run a server for other people, read
<<04-running-a-server.adoc#running-a-server,Running a server>>; it covers choosing addresses on a VPN or
LAN, firewalls, configuration files, robots, hosting for friends far away and running the server as a
service.

[[connect]]
== Joining a server

[source,shell]
----
java -jar jxpilot-client-VERSION.jar --connect HOST                  # a JXPilot server, port 15345
java -jar jxpilot-client-VERSION.jar --connect HOST:PORT --name Ace
java -jar jxpilot-client-VERSION.jar --connect xp://HOST             # an original XPilot 4.5.5 server
----

`HOST` is a name or an IP address; write IPv6 addresses in brackets with a port (`[2001:db8::1]:15345`).
If the server refuses you, the client shows why, for example `Rejected by HOST: name not accepted` when
your name is already taken (<<04-running-a-server.adoc#joining,Joining, leaving and full servers>>). All
client flags are in <<07-client-reference.adoc#client-reference,Client reference>>.
