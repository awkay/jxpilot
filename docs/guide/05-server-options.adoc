This chapter lists every server option. The tables are generated from the server's option registry
(`Opt` in the `common` module), and the build fails if they fall out of date, so they always match the
code of this release.

The option set is XPilot 4.5.5's, with XPilot's defaults and help texts, plus JXPilot's network options
(their help starts with "JXPilot:", in <<opts-network,Server and network>>). Every option is accepted
everywhere the table says, so original XPilot maps and config files load unchanged. Each option's
description starts with what the JXPilot server does with it:

[cols="2,5",options="header"]
|===
|Status |Meaning
|*Implemented* |The server uses the option as XPilot does.
|*In progress (M2)* |The option belongs to a feature being built: items, balls and treasures, targets,
races or asteroids. It takes effect when the feature arrives.
|*Not yet* |Not implemented, and not part of current work; the reason is given.
|*Not supported* |Deliberately left out; the reason is given.
|*No effect* |XPilot 4.5.5 itself never uses it.
|*Not applicable* |Has no meaning for the JXPilot server; the reason is given.
|===

The status comes from `docs/server-options-status.md` in the source, which records for every option
where the server uses it. Unknown option names are kept and ignored, as XPilot does.

[[reading-the-tables]]
== Reading the tables

Option:: The full name, as used in config and map files. Names are not case-sensitive, and spaces
inside them are ignored (`max robots` is `maxRobots`).
Short name:: An alternative name, usually the command-line name from XPilot (for example `port` for
`contactPort`). It works everywhere the full name does. Blank when there is none.
Type:: How the value is written:
+
[cols="1,4",options="header"]
|===
|Type |Values
|integer |A whole number. As in C: `0x1F` is hexadecimal and a leading `0` means octal (`010` is 8).
|real |A decimal number, with an optional exponent: `0.5`, `-0.14`, `5e-7`.
|boolean |`yes`, `on` or `true`; `no`, `off` or `false` (any case). On the command line, booleans
take no value: `-name` sets true and `+name` sets false.
|seconds |A time in seconds (a real number). The server converts it to frames using `framesPerSecond`.
|per second |A rate per second, converted to per frame using `framesPerSecond`.
|position `x,y` |Two integers separated by a comma, in blocks: `12,40`.
|text |Any text up to the end of the line; use `\multiline:` for several lines
(<<06-config-and-maps.adoc#multiline,Multiline values>>).
|comma list |Comma-separated values: `a,b,c`.
|switch (no value) |A command-line switch.
|===
Default:: The built-in value (XPilot's `cmdline.c`). _(none)_ means unset; _(empty)_ means the empty text.
When XPilot's `lib/defaults`, which the server reads at every start, sets another value, it follows as
"lib/defaults: ..." (<<04-running-a-server.adoc#defaults-file,The defaults file>>).
Set from:: Where the option may be set: `command line`, `map` (a map file), `config file` (the server
configuration file), and for `password` also the password file. A value from anywhere else is refused
with a warning. When an option is set in several places, the
<<06-config-and-maps.adoc#precedence,precedence rules>> pick the winner.
