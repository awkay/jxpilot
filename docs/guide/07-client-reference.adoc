This chapter lists every flag of the client: the game flags, the map viewer's flags, the Java options of
the jar launcher, and how to play on original XPilot servers.

[[client-synopsis]]
== Starting the client

The client has three modes:

[source,shell]
----
java -jar jxpilot-client-VERSION.jar --connect HOST[:PORT] [GAME FLAGS]   # join a server
java -jar jxpilot-client-VERSION.jar --local --map MAP [GAME FLAGS]       # play on a server of your own
java -jar jxpilot-client-VERSION.jar --view-map MAP [VIEWER FLAGS]        # look at a map
java -jar jxpilot-client-VERSION.jar --list-maps                          # print the built-in maps
----

The application downloads take the same flags (`JXPilot.app/Contents/MacOS/JXPilot ...` on macOS);
from source, `client/scripts/run-client.sh` (after a build) or
`mvn -pl client exec:exec -Dclient.args="..."` run the same main class.

Without arguments, the client prints its usage and exits with status 2, as it does for an unknown flag,
a missing value or a malformed number (with a message naming the flag). It also exits with 2 when
`--connect` and `--local` are both given, or `--map` without `--local`, or for a `--view-map` map that
is not found. A `--local` server that cannot start (for example an unknown map) exits with status 3.

[[client-map-names]]
=== Map names

`--map` and `--view-map` read their value as the server's `--map` does
(<<04-running-a-server.adoc#map-names,Choosing the map>>):

* A plain name (no `/` or `\`, no drive letter) is one of the 19 maps built into the jar, in any case
  and with or without `.xp`: `--map tourmination`, `--view-map PlanetX.xp`. `--list-maps` prints them
  with their size, title and author.
* A plain name that is not built in is a file in the current directory (`mymap`, then `mymap.xp`, then
  `mymap.map`).
* A value with a path in it is only a file: `./default.xp`, `maps/mymap.xp`, `C:\maps\mymap.xp`.

An unknown map is an error that lists the built-in names.

[[game-flags]]
== Game flags (`--connect` and `--local`)

[cols="2,2,4",options="header"]
|===
|Flag |Default |Meaning

|`--connect TARGET`
|-
|Join the server at `TARGET` (<<connect-targets>>).

|`--local`
|-
|Start a JXPilot server inside the client and join it. It listens on the loopback address only, on a
free port, with the server's defaults (robots included), and stops when you quit.

|`--map MAP`
|required with `--local`
|The map for `--local`: a built-in map name or a map file (<<client-map-names>>).

|`--list-maps`
|-
|Print the built-in maps (name, size, title, author) and exit. It wins over `--connect` and `--local`.

|`--protocol xpilot\|jxpilot`
|`jxpilot`
|With `--connect`: the protocol for a target without `xp://` or `jx://`.

|`--bind ADDR[:PORT]`
|any
|With `--connect`: the local address (and port) to send from, for example to make sure the game goes
over a VPN.

|`--name NAME`
|your login name
|Player name, 1 to 16 characters. The default keeps the letters, digits, `-`, `_` and `.` of your login
name, with a capital first letter (`Pilot` if nothing is left).

|`--team T`
|none
|Team 0 to 9 to join in team play. Without it the server picks one.

|`--shape SHAPE`
|the standard ship
|Your ship shape, in XPilot's shape format (as in a robots file, <<04-running-a-server.adoc#robot-file,Robot
personalities>>). The server uses it if it allows ship shapes.

|`--size WxH`
|`1280x800`
|Window size in logical pixels.

|`--scale-factor F`
|`1.0`
|XPilot's `scaleFactor`: the view is zoomed by 1/F (2 shows twice as much of the map).

|`--alt-scale-factor F`
|`2.0`
|XPilot's `altScaleFactor`: the zoom the swap key switches to.

|`--swap-scale-key KEYSYM`
|unbound
|Bind the zoom swap to an X11 key name such as `z` or `F5` (XPilot's `keySwapScaleFactor`).

|`--font FILE`, `--font-size PX`
|bundled Fira Code, 13
|Font for all text, and its size in logical pixels.

|`--sound`, `--no-sound`
|sound on
|Play sound effects or not (XPilot's `sound` resource; <<03-playing.adoc#sound,Sound>>).

|`--volume N`
|`100`
|XPilot's `maxVolume`, 0 to 255: the loudest a sound plays. `0` is no sound; above 100 plays like 100.

|`--screenshot FILE.png`, `--frames N`
|-, 300
|Save a PNG after N frames and exit (for tests and bug reports).

|`--no-vsync`
|vsync on
|Render as fast as possible.
|===

[[connect-targets]]
=== Connect targets

[cols="2,4",options="header"]
|===
|Target |Meaning
|`host`, `host:port` |A JXPilot server (port 15345 if none is given), unless `--protocol xpilot`.
|`192.0.2.7:15345`, `[2001:db8::1]:15345` |IP addresses; IPv6 in brackets when a port follows.
|`jx://host[:port]` |A JXPilot server, whatever `--protocol` says.
|`xp://host[:port]` |An original XPilot 4.5.5 server (<<xpilot-protocol>>).
|===

[[viewer-flags]]
== Viewer flags (`--view-map`)

[cols="2,1,4",options="header"]
|===
|Flag |Default |Meaning

|`--view-map MAP`
|required
|Open the free-flying map viewer on a built-in map or a map file (<<client-map-names>>). kbd:[Tab]
cycles through the built-in maps, or for a file through the other `.xp` files in its directory
(<<03-playing.adoc#map-viewer-keys,Map viewer keys>>).

|`--demo`
|off
|Animate fake ships, shots, particles, items and a HUD over the map, to show what the game draws.

|`--size WxH`
|`1280x800`
|Window size in logical pixels (on a Retina or HiDPI screen the framebuffer is larger).

|`--zoom Z`
|`1`
|Initial zoom; must be positive. The keys and mouse wheel zoom between 0.05 and 8.

|`--at X,Y`
|first base, else the map centre
|Initial camera centre in world pixels (one block is 35 pixels; y grows upwards).

|`--filled`
|off
|Draw walls filled instead of XPilot's default outlines (kbd:[F] toggles it).

|`--screenshot FILE.png`
|none
|Render, save a PNG of the window's framebuffer, print frame statistics and exit. Useful for
scripts and bug reports.

|`--frames N`
|`3`
|With `--screenshot`: frames to render before taking it (positive).

|`--warmup N`
|half of `--frames`
|With `--screenshot`: frames left out of the printed timing and allocation statistics (0 or more, less
than `--frames`).

|`--no-vsync`
|vsync on
|Render as fast as possible instead of at the display's refresh rate (for measuring frame rate).

|`--gpu-timer`
|off
|Measure GPU time per frame with OpenGL timer queries (costs CPU time on some drivers).

|`--alt-scale-factor F`
|`2.0`
|XPilot's `altScaleFactor`: the alternative zoom (1/F) that kbd:[S] swaps to; positive.

|`--font FILE`
|bundled Fira Code
|A TrueType font file for all text.

|`--font-size PX`
|`13`
|Text size in logical pixels; positive.

|`--demo-round-delay N`
|`0`
|With `--demo`: show a round-start countdown of N frames (0 or more).

|`--demo-damaged N`
|`0`
|With `--demo`: show N frames of ECM damage on the own ship from the start (0 or more).
|===

The viewer prints one line describing each map it loads, and with `--screenshot` the file written and
frame statistics, for example:

----
map planetx.xp  310x267  "Planet X": outline mesh 32325 segments, 0 triangles, 1036 points; filled mesh ...
screenshot out.png (2560x1600) after 30 frames, 1 world copies, 5 draw calls/frame
  frames 15..30: mean 8.318 ms (120 fps), p99 20.79 ms, max 20.78 ms; cpu before swap: mean 0.781 ms; ...
  render thread allocated 0 bytes over frames 15..30
----

[[launcher]]
== The jar launcher and Java options

The release client jar starts in a small launcher (`com.fulcrologic.jxpilot.dist.ClientLauncher`)
before the client itself:

* *On macOS*, GLFW must run on the process's first thread, which needs the Java option
  `-XstartOnFirstThread`. If Java was started without it, the launcher runs the same `java` again with
  the same class path, Java options and client flags, plus `-XstartOnFirstThread` and the recommended
  options below. The second process shares the terminal, and its exit status becomes the launcher's.
  Java debugger agents (`-agentlib:jdwp`) are not passed on, because the first process holds their port.
* *On Windows and Linux*, and on macOS when `-XstartOnFirstThread` is already set, it starts the client
  directly.

[cols="2,5",options="header"]
|===
|Environment variable |Effect
|`JXPILOT_NO_RELAUNCH=1` |Never start a second process. Any value except `0`, `false`, `no` or `off`
counts. On macOS the client then fails with "GLFW may only be used on the main thread" unless you pass
`-XstartOnFirstThread` yourself.
|`JXPILOT_RELAUNCHED` |Set by the launcher for the second process, so that it never starts a third.
Don't set it yourself.
|===

The recommended Java options, which the macOS relaunch adds when you have not chosen otherwise:

[cols="2,4",options="header"]
|===
|Option |Why
|`-XX:+UseZGC` |A low-pause garbage collector. Not added if you choose another collector (`-XX:+Use...GC`).
|`--enable-native-access=ALL-UNNAMED` |Lets LWJGL call native code without warnings. The jar's
manifest also says this, so plain `java -jar` needs no option for it.
|`--sun-misc-unsafe-memory-access=allow` |Silences the JDK warning about LWJGL's use of `sun.misc.Unsafe`.
|===

On Windows and Linux you can add them yourself:
`java -XX:+UseZGC --sun-misc-unsafe-memory-access=allow -jar jxpilot-client-VERSION.jar ...`.
The application downloads already include them.

[[test-clients]]
== Headless test clients

For testing servers without a window, the client jar contains two headless clients. They connect, run
the client's per-frame work and print a summary:

[source,shell]
----
java -cp jxpilot-client-VERSION.jar com.fulcrologic.jxpilot.client.net.ClientSim --connect HOST[:PORT]
java -cp jxpilot-client-VERSION.jar com.fulcrologic.jxpilot.client.xp.XpClientSim --connect xp://HOST --seconds 30
----

`ClientSim` (JXPilot servers) also takes `--bind ADDR[:PORT]`, `--name NAME` (default `jxsim`),
`--team T`, `--snapshots N` (stop after N snapshots, default 100) and `--seconds S` (give up after S
seconds, default 15). It exits with status 0 when it received the snapshots, 1 when it gave up or was
disconnected, and 2 for bad arguments.

[[xpilot-protocol]]
== Playing on original XPilot servers

The client also speaks the protocol of the original XPilot 4.5.5 server (`xpilots`), so you can play
on existing XPilot servers:

[source,shell]
----
java -jar jxpilot-client-VERSION.jar --connect xp://HOST            # or: --connect HOST --protocol xpilot
java -jar jxpilot-client-VERSION.jar --connect xp://HOST:15345 --name Ace --team 2
----

On an XPilot server everything works, items, balls and races included, because the C server runs the
game; the JXPilot client draws it with the same painters, HUD and keys. Known differences:

* XPilot sends only what is within 1024 x 1024 pixels of your ship.
* Paused ships carry no name on the wire, so the client cannot show their names or shapes.
* Bases on maps with a global gravity angle may be drawn facing the wrong way.
* Mouse (pointer) steering is not supported.
* XPilot server versions older than 4.5.5's protocol (0x4203 to 0x44ff) should work but were not
  tested.

The XPilot server needs its contact port (default 15345) and its player ports reachable. Developers can
run one locally in Docker with `client/scripts/xp-c-server.sh`; the protocol notes are in
`docs/XPILOT-PROTOCOL.md` in the source.
