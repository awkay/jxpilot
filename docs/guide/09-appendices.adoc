[appendix]
[[differences]]
== Differences from XPilot

JXPilot aims to play exactly like XPilot 4.5.5, and its server matches the XPilot server frame for frame
on recorded reference games. These are the deliberate differences a player or server operator may
notice. The complete list for developers, with the reasons, is in `docs/DEVIATIONS-server.md` in the
source.

[[differences-server]]
=== The JXPilot server

[cols="2,3,3",options="header"]
|===
|Area |XPilot |JXPilot
|Defaults file |`LIBDIR/defaults`; a missing file is skipped |XPilot's `lib/defaults` is in the jar;
`--defaults FILE` replaces it, `--defaults none` skips it, and a named file that cannot be read is an
error
|Player names |must start with a capital letter (the XPilot client capitalizes) |any non-empty name;
names already in use are refused, ignoring case
|Keys |every key press in a client packet counts |the server sees your keys once per frame; a key
pressed and released within one frame (1/14 s) is lost
|Random events |XPilot's random number generator |another generator: random details (sparks, explosions, robot
choices) differ, nothing else
|Exhaust sparks |drawn from the server's random numbers |every client computes the server's sparks
from the frame and the ship, so they are not sent; their push on other ships matches XPilot on
average, not frame for frame
|Connecting to a ball that was just destroyed |an XPilot bug |fixed
|`--map NAME` |a file in the current directory, then in the map directory (`MAPDIR`) |the 19 standard
maps are built into the jars and a plain name means one of them first; a file of the same name in the
current directory needs a path (`./default.xp`)
|`denyHosts` |only takes effect after an operator changes it during the game (an XPilot bug); IPv4; `:`
also separates entries |applies from the start; IPv4 and IPv6, so `:` does not separate entries
|`serverHost` |the address the contact socket binds |the bind selector when `--bind` is not given
|`logRobots` |on standard output |on the server log (standard error), with the other server messages
|Login queue |the client asks to join the queue and the server confirms its position every few
seconds |the client keeps asking every second and is told its position; the queue rules are XPilot's
|Ship shape |sent when you join |the same; a shape change during the game is ignored
|`/set` |connected clients see only what the server sends |the same: they keep the configuration they
got when they joined
|Wrong operator passwords |unlimited tries |after 3 wrong tries a wait of 10 seconds, doubling up to 5
minutes
|Option numbers |`inf` and `nan` are accepted |refused (the default at start-up, "invalid value" for
`/set`)
|Changing options over the network |an admin tool can list and change options through the contact port
|not available; operators use `/get` and `/set` in the game
|Password file |`LIBDIR/password` unless named otherwise; a missing file is skipped |read only when
`passwordFileName` names it; a named file that cannot be read is an error
|Network |XPilot's protocol, one port per player, meta server |JXPilot's protocol on one UDP port; no meta
server; the JXPilot client can still join XPilot servers
|===

=== The JXPilot client

[cols="2,3,3",options="header"]
|===
|Area |XPilot |JXPilot
|Quitting |the QUIT button or closing the window; no quit key |the same, plus kbd:[Cmd+Q] on macOS and an
optional `keyQuit` (unbound by default)
|kbd:[F1] |talk macro 1 |key help; talk macros are not supported
|Extra keys |- |kbd:[-] mutes sound, kbd:[Alt]/kbd:[Option] also connects, kbd:[0] also self-destructs
|Turn speed default |35 |40
|Engine sound |a short sound every frame |a loop while you thrust

90 ms behind the latest frame, your own ship predicted forward from it
|===

[[troubleshooting]]
== Troubleshooting

[cols="2,3",options="header"]
|===
|Problem |What to do

|`UnsupportedClassVersionError ... class file version 69.0`
|Your Java is older than 25. Install Java 25 (<<02-quick-start.adoc#java,Installing Java 25>>) and
check `java -version`.

|macOS: `GLFW may only be used on the main thread and that thread must be the first thread in the process`
|The client was started without `-XstartOnFirstThread`. With the release jar this only happens when
`JXPILOT_NO_RELAUNCH` is set; unset it, or add `-XstartOnFirstThread` to the `java` command.

|macOS: "JXPilot is damaged and can't be opened"
|The download is quarantined and the app is unsigned. Run `xattr -dr com.apple.quarantine JXPilot.app`
(<<02-quick-start.adoc#gatekeeper,details>>).

|The window does not open: errors mentioning GLFW, OpenGL or the display
|The client needs OpenGL 3.3 and a desktop session. Update the graphics driver; on Linux, check that
`DISPLAY` or `WAYLAND_DISPLAY` is set (it is not over plain SSH).

|Warnings about `sun.misc.Unsafe` at startup
|Harmless (LWJGL uses it). Add `--sun-misc-unsafe-memory-access=allow` to the `java` command to hide them.

|Server: `bind selector(s) [...] match no local address`
|The `--bind` selector matches no address on this machine. Check the interface name or network, or add
`--bindWait` if the interface appears later (<<04-running-a-server.adoc#bind-wait,bindWait>>).

|Server: `cannot bind ...` or "could not bind any address"
|Another program (perhaps another server) uses the port on that address. Stop it or choose another
`--port`.

|Players cannot connect
|Check that they use an address from the server's `listening on` lines, that the firewall allows the
UDP port (<<04-running-a-server.adoc#firewalls,Ports and firewalls>>), and that VPN users reach the
server over the VPN.

|Server: `option warning: Not allowed to change option '...' from MAP`
|The map sets an option that only the command line or config file may set. Harmless; the map's value is
ignored.

|Client: `Rejected by ...: name not accepted`, `server is full`, ...
|The server refused you; the reasons are listed in
<<04-running-a-server.adoc#joining,Joining, leaving and full servers>>. For a taken name, pick another
with `--name`.

|Client: stays at "connecting" and never starts
|Nothing comes back from the server. Check the address and port, that the server is running, and the
firewalls on both sides; the server answers only from the address you contacted
(<<04-running-a-server.adoc#multi-homed,Replies from the right address>>).

|Client: the game feels sluggish, your ship reacts late
|Your keys take a round trip to the server, plus the wait for its next frame (up to 1/14 s). Play on a
server closer to you, or host it half way between the players (<<04-running-a-server.adoc#hosting,Hosting for friends far away>>).

|Client: `jxpilot keys: ...` lines at startup
|Your `~/.xpilotrc` (or `--keys` file) has a line JXPilot cannot use, or a key bound to more than one
function. The message names the file and line; the rest of the file still applies. Check with
`--list-keys`.

|Client: `no sound: ...` at startup
|No audio device was found or the audio library could not load; the game plays without sound. Check
the system's sound output, or use `--no-sound` to skip the attempt.

|`--local`: `cannot start the local server: ...`
|The map file could not be read or has a bad option; the message says which.
|===

[appendix]
[[faq]]
== FAQ

Can I play JXPilot now?::
Yes: against robots with `--local`, on a JXPilot server with `--connect`, or on an original XPilot
server with `--connect xp://...`. The JXPilot server has the whole XPilot game; see
<<01-introduction.adoc#status,Status>> for what is still missing.

Can I join an original XPilot server, or use the original XPilot client with a JXPilot server?::
The JXPilot client joins original XPilot 4.5.5 servers with `xp://`
(<<07-client-reference.adoc#xpilot-protocol,Playing on original XPilot servers>>). The original XPilot
client cannot join a JXPilot server.

Does the server need a big machine?::
No: about 50-60 MB of memory and under 1% of a CPU core with six robots
(<<04-running-a-server.adoc#hosting,Hosting>>).

Does it use the original maps?::
Yes, unchanged. The 19 maps of the XPilot 4.5.5 distribution ship with it, and other block-based XPilot
maps should load too.

Can I use my XPilot server config files?::
Yes. JXPilot reads XPilot's config format and knows all XPilot 4.5.5 server options, with the same
precedence rules, so existing files load. Many options take effect only as the features are
implemented.

Can I use my `.xpilotrc` key bindings?::
Yes. JXPilot reads the key bindings and the six control settings from `~/.xpilotrc` in XPilot's format;
other resources are ignored with a note (<<03-playing.adoc#key-bindings,Changing the keys>>).

Is JXPilot related to the XPilot developers?::
No. It is an independent port; they were not involved and do not endorse it
(<<01-introduction.adoc#disclaimer,Relationship to XPilot>>).

Why is the client jar about 10 MB?::
It carries the native libraries (graphics and sound) for every supported system, so one file runs on
Windows, macOS and Linux, and the sound effects. The application downloads are larger because they include a Java runtime.

Does it run on Intel Macs, Linux on ARM, Windows on ARM?::
The jar includes native libraries for macOS on Intel and Apple Silicon, Linux on x64 and arm64, and
Windows on x64. The machine also needs an OpenGL 3.3 driver. Windows on ARM is not included yet.

Where do I report bugs?::
At https://github.com/awkay/jxpilot/issues. Please include your system, `java -version`, the command
you ran and its output.
